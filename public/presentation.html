PTV Journey Planner

A real-time public transport planning app for Melbourne, combining Google APIs, PTV live data, and a full RESTful backend.

Node.js + Express MongoDB Google APIs PTV API v3 JWT Auth API Keys

The Problem

Pain point

Melbourne commuters juggle multiple disconnected apps just to complete one journey.

  • No single tool handles route planning, live departure tracking, and nearby places together — you're constantly switching apps
  • Regular commuters can't save their daily route anywhere — they repeat the exact same search every single day
  • Multi-leg journeys (train + tram + bus) are fragmented — each leg is managed in a different place with no unified view
  • Finding a café or restaurant near your destination means leaving the transport app entirely and starting over

The Solution

What I built

A journey planner that combines routing, live departures, delays, and nearby places — all in one page.

  • Real-time routing computes the best transit path, broken into individual legs (train, tram, bus)
  • Delays are detected automatically by comparing live arrival data against the official timetable
  • Users can save their favourite routes and reopen them with one click — no re-searching
  • Nearby points of interest (cafés, restaurants, hotels) shown on the same map, no extra app needed
  • Full RESTful API with JWT authentication, API keys, CORS, and proper HTTP error codes

Key Features

🗺️

Journey Planning

Type any origin and destination — autocomplete finds it, the route is planned and broken into individual train/tram/bus legs.

🚆

Live Departures + Delays

Each leg shows upcoming departures. If real-time data differs from the official timetable, a delay alert appears automatically.

⭐

Saved Routes

Login to save your frequent journeys. Click Plan to reopen any route instantly, with optional nearby places attached.

📍

Nearby Places

After planning a route, find cafés, restaurants, hotels or hospitals near your destination — shown on the same map.

API Security

🔐

JWT Authentication

All user-specific routes (saved routes, API keys) require a Bearer token. Tokens are signed with a secret and expire automatically.

🗝️

API Key System

Developer-facing routes (/board, /common-alerts, /ptv-leg) require an X-Api-Key header. Keys are stored in MongoDB and can be revoked at any time.

🌐

CORS Policy

Only origins listed in ALLOWED_ORIGINS (.env) can call the API. Requests from any other domain are rejected by the browser.

🛡️

Security Headers

X-Content-Type-Options: nosniff and X-Frame-Options: DENY added to every response to prevent common browser attacks.
